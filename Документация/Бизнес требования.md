## 1. Общее описание проекта

**Название:** Local Messenger (Локальный мессенджер)  
**Тип проекта:** Учебный, клиент-серверное приложение  
**Статус:** В активной разработке, версия 1.1

### Краткое описание
Локальный мессенджер — это учебный проект, демонстрирующий навыки создания клиент-серверных приложений. Система предназначена для обмена сообщениями в локальной сети и постоянно развивается с добавлением новых функций.

**Новые возможности в версии 1.1:**
- ✅ **Динамическое обнаружение серверов** через UDP broadcast
- ✅ **Создание и запуск серверов** прямо из клиента
- ✅ **Парольная защита серверов** (запуск только по паролю)
- ✅ **Темная тема интерфейса** и кастомизация
- ✅ **Система уведомлений** (Desktop + звуковые)
- ✅ **Управление несколькими серверами**

**Фактические особенности:**
- Работа в локальной сети (автоматическое обнаружение)
- Клиент на PyQt5 + сервер на FastAPI
- Real-time через WebSocket
- JWT аутентификация
- SQLite база данных

### 5.2. Сетевые требования (обновленные):

**Для клиента:**
- Поддержка UDP broadcast (для обнаружения серверов)
- Открытые порты 37020 (UDP) для broadcast
- Доступ к порту 8000 (TCP) выбранного сервера

**Для сервера:**
- **Статический или динамический IP** - клиенты найдут автоматически
- **Открытые порты:**
  - 8000 (TCP) - основной сервер
  - 37020 (UDP) - broadcast сервер
- Поддержка multicast/broadcast в сети

### 5.3. Процесс обнаружения сервера:

```
1. Клиент отправляет UDP broadcast на порт 37020
2. Все запущенные серверы отвечают своей информацией
3. Клиент собирает ответы в течение таймаута (1.5-3 сек)
4. Список серверов отображается в интерфейсе
5. Пользователь выбирает сервер для подключения
6. Клиент подключается к выбранному серверу по HTTP/WebSocket
```

### 5.4. Процесс запуска защищенного сервера:

```
1. Пользователь выбирает защищенный сервер (🔒) в списке
2. Система запрашивает пароль
3. Клиент запускает сервер с переданным паролем
4. Сервер проверяет пароль через server_auth.py
5. При успехе - сервер запускается
6. Клиент подключается к запущенному серверу
```

### 7.2. Сценарии использования (обновленные):

#### Сценарий 1: Создание первого сервера
```
1. Пользователь запускает клиент
2. Серверов в сети не найдено
3. Клиент предлагает создать сервер
4. Пользователь создает сервер (с паролем или без)
5. Сервер автоматически запускается
6. Пользователь регистрируется и входит в систему
7. Сервер теперь доступен для других в сети
```

#### Сценарий 2: Подключение к существующему серверу
```
1. Пользователь запускает клиент
2. Клиент автоматически находит серверы в сети
3. Пользователь видит список доступных серверов
4. Выбирает нужный сервер (видит защиту паролем)
5. Вводит логин/пароль для входа
6. Начинает общение с другими пользователями
```

#### Сценарий 3: Запуск защищенного сервера
```
1. Пользователь видит в списке защищенный сервер (🔒)
2. Сервер не запущен (⚫), но сохранен в системе
3. Пользователь нажимает "Запустить сервер"
4. Система запрашивает пароль
5. При вводе правильного пароля сервер запускается
6. Пользователь подключается к запущенному серверу
```

#### Сценарий 4: Настройка внешнего вида
```
1. Пользователь открывает диалог настроек
2. Переходит на вкладку "Оформление"
3. Выбирает темную тему из списка
4. Интерфейс мгновенно меняется
5. Настройки сохраняются для следующих запусков
```

#### Сценарий 5: Получение уведомлений
```
1. Пользователь свернул приложение в трей
2. Приходит новое сообщение
3. Появляется desktop-уведомление
4. Проигрывается звуковой сигнал
5. Пользователь кликает на уведомление - открывается чат
```
